27. (370.7–389.2) So what happens when you start an E X E? Windows creates a process: a private address space. It maps the sections of the file into it. And it starts a thread at the entry point. The process is the container. The thread is what actually runs.

30. (419.1–438.4) It asked in its import table: a list, inside the E X E, of the functions it needs from other files. My code called F open, F write and F read. Underneath, those became Create File, Write File and Read File, from kernel thirty-two.
31. (438.4–455.6) This is the Windows A P I. A program cannot touch the disk, the screen or the keyboard by itself. It asks Windows. Kernel thirty-two: files, memory, processes. User thirty-two: windows and input.
32. (455.6–472.7) Now the game's import table. Open G L: that is how it draws. Open A L: sound. S D L: its window. Winsock: the network. An import table is a quick summary of what a program does.
33. (472.7–486.4) And Cheat Engine is a program too. Its own import table: Open Process. Read Process Memory. Write Process Memory. Reading a game's memory is a request to Windows.
34. (486.4–505.7) Let's recap. A file is bytes at offsets. A save file is often just a structure, written to disk. An E X E is a P E file: its image base and its sections become the memory map. And a program reaches Windows through its import table.
