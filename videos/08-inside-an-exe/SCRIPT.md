# Narration: What's Inside an EXE

Voiced with Azure Speech (en-US-AvaMultilingualNeural, rate -4%). Generated by build.py.

1. (0.0–10.8) Double-click a game, and Windows has to answer two questions. Where does this file go in memory? And what does it need? Both answers are inside the file.
2. (10.8–22.6) Every Windows program starts with two letters, M Z. A little further in come the headers: a table of contents for the whole file. After them, the sections.
3. (22.6–33.4) The sections are the body of the file. Dot text holds the code. Dot data holds the variables. Each one gets its own permissions when it is loaded.
4. (33.4–43.7) The headers name a preferred address: the image base. Add an offset from it, called an R V A, and you have a real address in memory.
5. (43.7–54.5) A game does not contain Windows. It only lists the functions it needs, in the import table. Windows fills in the real addresses at load time.
6. (54.5–66.6) So read the imports, and the file tells on itself. Open process, read process memory, write process memory: this program reaches into other programs.
7. (66.6–75.1) An executable is a map of itself. Learn to read the map before you read the code.
