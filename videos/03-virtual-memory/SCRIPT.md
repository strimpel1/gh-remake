# Narration: Why the Address Changes

Voiced with Azure Speech (en-US-AvaMultilingualNeural, rate -4%). Generated by build.py.

1. (0.0–11.0) Yesterday you found your health at this address. Today you restart the game, and the same address holds garbage. Nothing broke. It moved.
2. (11.0–20.4) Every process lives in its own private map of memory. The same address in two programs is two different places.
3. (20.4–32.0) The map has regions. The game's own file, loaded as a module. The heap, where it creates things while running. And a stack for every thread.
4. (32.0–41.6) Each page of memory carries permissions. Code can be read and run, but not written. Data can be written, but not run.
5. (41.6–47.9) Your player is created on the heap, so it lands somewhere new on every run.
6. (47.9–56.3) Even the module moves. Windows loads it at a random base each time. That is A S L R.
7. (56.3–64.9) But the distance from the start of the module never changes. Base plus offset finds the same spot every time.
8. (64.9–72.5) Never save an address. Save the module and the offset.
