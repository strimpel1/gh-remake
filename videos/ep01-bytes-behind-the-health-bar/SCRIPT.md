6. (52.7–63.4) Start with the smallest piece. Memory is a very long row of boxes. Each box is one byte, and every byte has its own address.
7. (63.4–70.6) A byte is eight switches, called bits. Each bit is off or on. Zero or one.
8. (70.6–81.4) Each bit has a place value, and every place is worth double the one to its right. One, two, four, eight, all the way up to one hundred twenty-eight.
9. (81.4–95.6) To store one hundred, switch on sixty-four, thirty-two, and four. Add them up: one hundred. So in binary, our health is zero one one zero, zero one zero zero.
10. (95.6–104.4) With all eight bits on, a byte holds two hundred fifty-five. That is the largest number one byte can store.
11. (104.4–114.3) Binary is exact, but nobody wants to read eight digits for every byte. So tools use hexadecimal: base sixteen.
12. (114.3–123.6) Hex has sixteen digits. Zero to nine, then A for ten, B for eleven, up to F for fifteen.
13. (123.6–139.2) And here is the trick. One hex digit is exactly four bits. So split the byte in half. Zero one one zero is six. Zero one zero zero is four. One hundred is hex six four.
14. (139.2–157.2) You don't have to trust me. Windows Calculator has a programmer mode. Type one hundred, and it shows the same number three ways. Decimal: one hundred. Hex: six four. Binary: zero one one zero, zero one zero zero.
15. (157.2–173.2) To avoid confusion, hex numbers are written with a zero x in front. Zero x one zero is not ten. It is sixteen. And zero x F F is two hundred fifty-five: a full byte in two digits.
16. (173.2–189.4) Bigger hex numbers work the same way as decimal, only the places are powers of sixteen. Zero x one F four: one times two hundred fifty-six, plus fifteen times sixteen, plus four. Five hundred.
17. (189.4–206.6) This is why every tool in this series shows memory in hex. Two digits, one byte, and the columns line up. On the left, the address of each row. In the middle, the bytes. On the right, the same bytes shown as text.
18. (206.6–218.3) So one byte tops out at two fifty-five. But ammo, money and score get much bigger than that. A program solves it by using several bytes side by side.
19. (218.3–232.9) In C and C plus plus, the type decides how many. A char is one byte. A short is two. An int is four, good for about four billion values. A long long is eight.
20. (232.9–241.8) The game stores health as a four byte integer. That is why we saw four bytes: six four, then three zeros.
21. (241.8–251.6) But look at the order. The six four comes first, and the zeros come after. If you wrote this number on paper, it would be the other way round.
22. (251.6–268.0) This is called little endian: the smallest part of the number is stored first. Take one thousand. In hex, that is three E eight. In memory, it becomes E eight, zero three, zero zero, zero zero.

24. (286.3–300.0) And minus one? Four bytes of F F. A signed integer uses the top half of its range for negative numbers. Read those same bytes as unsigned, and you get more than four billion.
25. (300.0–312.7) Not everything is a whole number. Positions, speeds and angles need a decimal point. For those, programs use a float: four bytes with a completely different layout.
26. (312.7–325.6) A float splits its thirty-two bits into three parts. One bit for the sign, eight for the exponent, and twenty-three for the fraction. It is scientific notation, in binary.

29. (352.5–364.8) It works the other way too. Health is one hundred. Read its bytes as a float, and you get one point four, times ten to the minus forty-three. Practically zero.
30. (364.8–373.0) Memory does not store types. It only stores bytes. The type is a decision made by whoever is reading.
31. (373.0–386.4) Even text works this way. My player name is pixel. In memory, it is five bytes: seven zero, six nine, seven eight, six five, six C. One number per letter.

34. (418.4–430.7) This is why every memory scanner asks you for a value type before it searches. Pick four bytes when the game uses a float, and you will find nothing, even though the value is right there.
