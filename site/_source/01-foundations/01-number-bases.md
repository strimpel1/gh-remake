# שיעור 1.1 — בסיסי ספירה: בינארי, עשרוני והקסדצימלי

**מודול:** יסודות · **יחידות מקור:** CS420 3 - Base Systems: Hex, Decimal & Binary

## הרעיון בקצרה

מחשב שומר הכול כביטים — אפסים ואחדים. לקרוא שורות ארוכות של ביטים זה סיוט, ולכן כל כלי בתחום מציג זיכרון ב-**hexadecimal** (בקיצור hex), בסיס 16. הסיבה היא נוחות טהורה: ספרת hex אחת היא בדיוק ארבעה ביטים, ושתי ספרות hex הן בדיוק בית (byte) אחד. מי שקורא hex בשטף קורא זיכרון.

## אותו מספר, שלוש כתיבות

בסיס ספירה קובע כמה ספרות יש לנו, ומה שווה כל מקום במספר. בעשרוני כל מקום שווה פי 10 מהקודם. בבינארי פי 2. ב-hex פי 16.

| בסיס | ספרות | סימון מקובל | המספר 255 |
|------|-------|-------------|-----------|
| Binary (2) | 0, 1 | `0b` בהתחלה | `0b11111111` |
| Decimal (10) | 0–9 | בלי סימון | `255` |
| Hexadecimal (16) | 0–9, A–F | `0x` בהתחלה, או `h` בסוף | `0xFF` |

ב-hex האותיות ממשיכות את הספירה: A=10, B=11, C=12, D=13, E=14, F=15.

חשוב להבין שאלה שלוש **דרכי כתיבה** של אותו ערך. בזיכרון יש רק ביטים. הכלי הוא שמחליט איך להציג אותם.

## למה דווקא hex

כי ההמרה בין hex לבינארי היא החלפה פשוטה, ספרה מול ארבעה ביטים, בלי שום חישוב:

| Hex | Binary | Hex | Binary |
|-----|--------|-----|--------|
| 0 | 0000 | 8 | 1000 |
| 1 | 0001 | 9 | 1001 |
| 2 | 0010 | A | 1010 |
| 3 | 0011 | B | 1011 |
| 4 | 0100 | C | 1100 |
| 5 | 0101 | D | 1101 |
| 6 | 0110 | E | 1110 |
| 7 | 0111 | F | 1111 |

לכן `0xC8` הוא `1100 1000`, וזהו. ההמרה מעשרוני לבינארי דורשת חישוב אמיתי, וזו הסיבה שעשרוני לא נוח לקריאת זיכרון.

כדאי לזכור גם את הגדלים:

- **Bit** — ספרה בינארית אחת.
- **Nibble** — ארבעה ביטים, ספרת hex אחת.
- **Byte** — שמונה ביטים, שתי ספרות hex. טווח: `0x00` עד `0xFF` (0 עד 255).
- ארבעה בתים הם שמונה ספרות hex. כתובת בתהליך של 32 ביט נראית כך: `0x00F8A3C0`.

## המרה מ-hex לעשרוני

מכפילים כל ספרה בערך המקום שלה ומחברים. המקומות, מימין לשמאל: 1, 16, 256, 4096.

```
0x3E8  =  3*256 + 14*16 + 8*1
       =  768   + 224   + 8
       =  1000
```

## המרה מעשרוני ל-hex

מחלקים ב-16 שוב ושוב ורושמים את השאריות. השארית האחרונה היא הספרה השמאלית.

```
1000 / 16 = 62   remainder 8
  62 / 16 = 3    remainder 14 (E)
   3 / 16 = 0    remainder 3

read bottom to top:  3 E 8  ->  0x3E8
```

בפועל אף אחד לא עושה את זה על נייר. פותחים את המחשבון של Windows במצב **Programmer**, שמציג את אותו ערך ב-HEX, DEC, OCT ו-BIN בו-זמנית. התרגול הידני נועד רק כדי שהמספרים יפסיקו להיראות מאיימים.

## חשבון ב-hex: מה שבאמת עושים כל יום

השימוש היומיומי הוא חיבור של כתובת ו-offset. מבנה השחקן מתחיל ב-`0x00F8A3C0`, והחיים שלו נמצאים `0xEC` בתים אחריו:

```
  0x00F8A3C0
+ 0x000000EC
------------
  0x00F8A4AC
```

עובדים כמו בחיבור רגיל, רק שנושאים 1 כשמגיעים ל-16 ולא ל-10: `C0 + EC` = 192 + 236 = 428 = `0x1AC`, כלומר רושמים `AC` ונושאים 1 לספרה הבאה.

כמה ערכים שחוזרים כל הזמן וכדאי לזהות במבט:

| Hex | עשרוני | איפה פוגשים אותו |
|-----|--------|-------------------|
| `0x10` | 16 | צעד נפוץ בין שדות ובין שורות בתצוגת זיכרון |
| `0x64` | 100 | ערך התחלתי אופייני לחיים |
| `0xFF` | 255 | הערך המרבי של בית |
| `0x100` | 256 | |
| `0x3E8` | 1000 | |
| `0x1000` | 4096 | גודל עמוד זיכרון (page) |
| `0x7FFFFFFF` | 2,147,483,647 | הערך המרבי של מספר שלם בן 4 בתים עם סימן |
| `0xFFFFFFFF` | 4,294,967,295 או 1- | תלוי אם קוראים אותו עם סימן או בלי. על זה בשיעור הבא |

## מלכודות נפוצות

- **לשכוח באיזה בסיס הכלי מציג.** ב-Cheat Engine ערכים מוצגים כברירת מחדל בעשרוני וכתובות ב-hex. `100` בעמודת הערך ו-`100` בעמודת הכתובת הם שני מספרים שונים.
- **`0x10` הוא לא עשר.** זה 16. הטעות הזו אחראית לחלק נכבד מה-offsets השגויים של מתחילים.
- **hex בלי סימון.** ב-debugger מספרים מופיעים הרבה פעמים בלי `0x`. אם יש בהם אותיות A–F זה ברור, אבל `20` יכול להיות 32. כשיש ספק, מניחים hex.

## מילון מונחים

| מונח | משמעות |
|------|--------|
| **Bit** | ספרה בינארית, 0 או 1 |
| **Nibble** | ארבעה ביטים, ספרת hex אחת |
| **Byte** | שמונה ביטים, שתי ספרות hex |
| **Hexadecimal** | בסיס 16, הספרות 0–9 ו-A–F |
| **Prefix `0x`** | סימון שאומר שהמספר שאחריו כתוב ב-hex |
| **Offset** | מרחק בבתים מכתובת בסיס |

## בדיקה עצמית

1. כמה ספרות hex צריך כדי לכתוב ערך של שני בתים?
2. מהו `0x2A` בעשרוני? ומהו 200 ב-hex?
3. כתבו את `0xB4` בבינארי בלי לחשב.
4. מבנה מתחיל ב-`0x0040F010` והשדה שמחפשים נמצא ב-offset `0xF8`. מה הכתובת שלו?
5. למה `0x10 + 0x10` הוא `0x20` ולא `0x100`?

תשובות: (1) ארבע. (2) 42, ו-`0xC8`. (3) `1011 0100`. (4) `0x0040F108`. (5) כי 16 + 16 = 32, ו-32 הוא שתי "שש-עשרות" ואפס יחידות.
