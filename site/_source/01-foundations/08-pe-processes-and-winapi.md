# שיעור 1.8 — קובץ PE, תהליכים ו-Windows API

**מודול:** יסודות · **יחידות מקור:** Windows PE File Format, Windows Internals - Processes and Threads, What is the Windows API

## הרעיון בקצרה

שלושה מושגים סוגרים את מסלול היסודות. **קובץ PE** הוא הפורמט של כל EXE ו-DLL ב-Windows: הוא מתאר ל-Windows איך לפרוש את הקובץ בזיכרון. **תהליך** הוא מה שנוצר כשהקובץ הזה נטען ומתחיל לרוץ. ו-**Windows API** הוא אוסף הפונקציות שדרכן כל תוכנה, כולל הכלים שנכתוב, מבקשת דברים ממערכת ההפעלה. כל טכניקה במסלולים הבאים נשענת על שלושתם.

## מבנה של קובץ PE

```
+---------------------------+
| DOS header     ("MZ")     |  e_lfanew -> where the PE header starts
+---------------------------+
| PE signature   ("PE\0\0") |
| File header               |  machine type, number of sections
| Optional header           |  ImageBase, AddressOfEntryPoint, data directories
+---------------------------+
| Section table             |  one row per section: name, sizes, addresses, permissions
+---------------------------+
| .text    code             |
| .rdata   constants, imports
| .data    global variables |
| .rsrc    icons, dialogs   |
| .reloc   relocations      |
+---------------------------+
```

השדות שחוזרים שוב ושוב בעבודה:

| שדה | מה הוא אומר |
|-----|---------------|
| `Machine` | לאיזה מעבד הקובץ נבנה: `0x14C` הוא 32 ביט, `0x8664` הוא 64 ביט |
| `ImageBase` | הכתובת שבה הקובץ מעדיף להיטען. עם ASLR הוא ייטען במקום אחר |
| `AddressOfEntryPoint` | ה-RVA של ההוראה הראשונה שרצה |
| `SizeOfImage` | כמה מקום הקובץ תופס בזיכרון אחרי הטעינה |
| Data directories | מצביעים לטבלאות: imports, exports, relocations ועוד |

## שלוש כתובות שונות לאותו בית

| מונח | נמדד מ- | דוגמה |
|------|---------|-------|
| **File offset** | תחילת הקובץ על הדיסק | `0x0000A400` |
| **RVA** | תחילת ה-module בזיכרון | `0x0000B000` |
| **VA** | אפס של מרחב הכתובות | `0x0040B000` |

VA הוא תמיד base ועוד RVA. ה-file offset שונה מה-RVA כי כל section מיושר אחרת בקובץ ובזיכרון. ההמרה נעשית לפי טבלת ה-sections:

```
file offset = RVA - section.VirtualAddress + section.PointerToRawData
```

זה החישוב שחסר בשיעור 1.6, כשרצינו לכתוב patch ישירות לקובץ.

## Imports ו-Exports

תוכנה לא מכילה את הקוד של `MessageBoxA`. היא רק מצהירה שהיא צריכה אותו.

- **Import table** — רשימת הפונקציות שהקובץ צריך מ-DLLs אחרים. בזמן הטעינה Windows ממלא את ה-**IAT** (Import Address Table) בכתובות האמיתיות, והקוד קורא לפונקציות דרך הטבלה הזו.
- **Export table** — רשימת הפונקציות ש-DLL מציע לאחרים, לפי שם או מספר.

שתי תובנות מעשיות:

- רשימת ה-imports היא תקציר מהיר של מה שתוכנה עושה. תוכנה שמייבאת `OpenProcess`, `ReadProcessMemory` ו-`WriteProcessMemory` נוגעת בזיכרון של תהליכים אחרים. זה הצעד הראשון בכל ניתוח, ונחזור אליו במסלול ה-Malware.
- מכיוון שכל קריאה חיצונית עוברת דרך ה-IAT, מי שמחליף כתובת בטבלה מיירט את הקריאה. זו טכניקת hooking שנלמד במסלול 6.

כלים להצצה בקובץ PE: PE-bear, CFF Explorer, או `dumpbin /headers` שמגיע עם Visual Studio.

## תהליך, Thread ו-Handle

| מושג | מה זה |
|------|-------|
| **Process** | מכל: מרחב כתובות פרטי, modules טעונים, handles והרשאות. הוא עצמו לא מריץ קוד |
| **Thread** | מה שבאמת רץ. לכל thread יש stack משלו וערכי registers משלו. לכל תהליך יש לפחות אחד |
| **PID / TID** | המספר המזהה של תהליך ושל thread |
| **Handle** | מספר שמייצג גישה לאובייקט של המערכת: תהליך, קובץ, thread. מקבלים אותו מה-API ומוסרים אותו חזרה בקריאות הבאות |
| **Module** | קובץ PE שנטען לתהליך |

למשחק יש בדרך כלל עשרות threads: רינדור, סאונד, רשת, לוגיקה. כולם חולקים את אותו זיכרון, ולכן קוד שנכניס לתהליך יכול לרוץ במקביל ללוגיקת המשחק. זה נוח, וזה גם מקור לבאגים של תזמון.

## Windows API

ה-API מוצהר בקובץ הכותרת `windows.h` וממומש ב-DLLs של המערכת: `kernel32.dll` (תהליכים, זיכרון, קבצים), `user32.dll` (חלונות, קלט), `ntdll.dll` (השכבה שמתחת, שמדברת עם ה-kernel).

הפונקציות שנפגוש שוב ושוב:

| פונקציה | מה היא עושה | איפה בקורס |
|---------|-------------|-------------|
| `OpenProcess` | מחזירה handle לתהליך לפי PID | מסלול 4 |
| `ReadProcessMemory` / `WriteProcessMemory` | קריאה וכתיבה בזיכרון של תהליך אחר | מסלול 4 |
| `VirtualProtect` / `VirtualAllocEx` | שינוי הרשאות עמוד, הקצאת זיכרון | מסלולים 4–5 |
| `CreateToolhelp32Snapshot` | מעבר על רשימת התהליכים וה-modules | מסלול 4 |
| `GetModuleHandle` / `GetProcAddress` | מציאת base של module וכתובת של פונקציה מיוצאת | מסלולים 5–6 |
| `CreateRemoteThread` / `LoadLibrary` | יצירת thread בתהליך אחר, טעינת DLL | מסלול 5 |
| `CloseHandle` | שחרור handle | תמיד |

כמה מוסכמות שחוסכות בלבול:

- **סיומות A ו-W.** `MessageBoxA` מקבלת מחרוזות ANSI, `MessageBoxW` מקבלת UTF-16. השם בלי סיומת הוא macro שבוחר ביניהן.
- **טיפוסים משלהם.** `DWORD` הוא 4 בתים בלי סימן, `HANDLE` הוא handle, `LPVOID` הוא pointer כללי, `BOOL` הוא int.
- **בודקים הצלחה.** רוב הפונקציות מחזירות 0 או `NULL` בכישלון, ואת הסיבה מקבלים מ-`GetLastError()`. הסיבה הנפוצה ביותר בתחילת הדרך היא קוד 5, `ERROR_ACCESS_DENIED`: התוכנה שלכם לא רצה כמנהל, או שביקשתם הרשאות שהמערכת לא נותנת.

## מה הלאה

כאן מסתיימים היסודות. יש לכם עכשיו את אוצר המילים המלא: בתים וטיפוסים, מפת הזיכרון של תהליך, pointers, קריאת Assembly, הסכמי קריאה ומבנה הקובץ שממנו הכול נטען. במסלול 2 לוקחים את כל זה ל-Cheat Engine ומתחילים למצוא דברים במשחק אמיתי.

## מילון מונחים

| מונח | משמעות |
|------|--------|
| **PE** | Portable Executable, פורמט קובצי EXE ו-DLL ב-Windows |
| **ImageBase** | כתובת הטעינה המועדפת של הקובץ |
| **Entry point** | ההוראה הראשונה שרצה בקובץ |
| **RVA / VA** | כתובת יחסית ל-base, וכתובת מוחלטת בזיכרון |
| **IAT** | טבלת הכתובות של הפונקציות המיובאות |
| **Export** | פונקציה ש-DLL מציע לשימוש חיצוני |
| **Handle** | מזהה שמייצג גישה לאובייקט של מערכת ההפעלה |
| **Thread** | יחידת ריצה בתוך תהליך |

## בדיקה עצמית

1. קובץ נטען ב-base `0x00D20000` וה-entry point שלו ב-RVA `0x1530`. מה ה-VA?
2. section מתחיל ב-`VirtualAddress = 0x1000` וב-`PointerToRawData = 0x400`. מה ה-file offset של RVA `0x1250`?
3. מה אפשר ללמוד על תוכנה רק מרשימת ה-imports שלה?
4. מה ההבדל בין תהליך ל-thread?
5. `OpenProcess` החזירה `NULL` ו-`GetLastError` החזירה 5. מה הסיבה הסבירה?

תשובות: (1) `0x00D21530`. (2) `0x650`. (3) באילו יכולות של המערכת היא משתמשת: קבצים, רשת, זיכרון של תהליכים אחרים. (4) תהליך הוא המכל של הזיכרון והמשאבים. thread הוא מה שמריץ קוד בתוכו. (5) אין הרשאה: צריך להריץ כמנהל, או לבקש פחות הרשאות.
