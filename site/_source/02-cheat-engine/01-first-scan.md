# שיעור 2.1 — Cheat Engine: התקנה וסריקה ראשונה

**מודול:** סריקת זיכרון עם Cheat Engine · **יחידות מקור:** Install Cheat Engine (GH101), Ultimate Cheat Engine Beginner Tutorial Part 1 (GH102)

## הרעיון בקצרה

Cheat Engine (בקיצור CE) הוא סורק זיכרון: הוא עובר על כל הזיכרון של תהליך ומחפש ערך שאתם מבקשים. הטריק שעליו הכול נשען הוא **סינון חוזר**: מחפשים ערך, משנים אותו במשחק, ומחפשים שוב רק בין התוצאות הקודמות. אחרי שלושה או ארבעה סיבובים נשארת כתובת אחת. זה מה שעשינו "על נייר" במסלול היסודות, ועכשיו עושים את זה באמת.

## התקנה בלי הפתעות

- מורידים רק מהאתר הרשמי, `cheatengine.org`, או מדף ה-GitHub של הפרויקט.
- המתקין הרשמי מציע תוכנות נלוות. בכל מסך שמציע משהו שאינו Cheat Engine לוחצים Decline או Skip, ולא Next באופן אוטומטי.
- Antivirus יתריע על CE. זה צפוי: כלי שקורא וכותב לזיכרון של תהליכים אחרים נראה חשוד מעצם טבעו. עדיף לעבוד בתוך VM, כמו שהמלצנו בשיעור 0.1.
- CE כולל תרגיל מובנה: בתפריט Help בוחרים Cheat Engine Tutorial. זו מטרת התרגול המושלמת לשיעור הזה, והיא בטוחה לחלוטין.

## החלון הראשי

| אזור | מה עושים בו |
|------|--------------|
| כפתור התהליך (אייקון מחשב, משמאל למעלה) | בוחרים לאיזה תהליך להתחבר |
| **Value** | הערך שמחפשים |
| **Scan Type** | סוג ההשוואה: ערך מדויק, גדל, קטן ועוד |
| **Value Type** | טיפוס הנתון: 4 Bytes, Float וכן הלאה |
| **First Scan / Next Scan** | סריקה חדשה, או סינון של התוצאות הקיימות |
| רשימת התוצאות (משמאל) | כתובות שעברו את הסינון. המספר מעליה, Found, הוא הכמות |
| **Address list** (למטה) | הכתובות ששמרתם לעבודה |

## הסריקה הראשונה, צעד אחר צעד

נניח שבתרגיל המובנה יש לכם 100 נקודות חיים.

1. **מתחברים לתהליך.** לוחצים על אייקון המחשב ובוחרים את התהליך מהרשימה.
2. **סריקה ראשונה.** ב-Value כותבים `100`, Scan Type נשאר Exact Value, Value Type נשאר 4 Bytes. לוחצים First Scan. יתקבלו אלפי תוצאות: בזיכרון של כל תהליך יש המון מקומות שמכילים במקרה 100.
3. **משנים את הערך במשחק.** בתרגיל לוחצים Hit me, והחיים יורדים ל-97, למשל.
4. **סינון.** כותבים `97` ולוחצים **Next Scan** (לא First Scan, שמוחק את התוצאות ומתחיל מחדש). נשארות רק כתובות שהיו 100 ועכשיו הן 97.
5. **חוזרים על 3 ו-4** עד שנשארת כתובת אחת, או קומץ.
6. **מוסיפים לרשימה.** לחיצה כפולה על הכתובת מורידה אותה ל-Address list.
7. **משנים.** לחיצה כפולה על העמודה Value ברשימה התחתונה, כותבים `1000`, והערך במשחק משתנה.

## להקפיא ערך

תיבת הסימון בעמודה **Active** מקפיאה כתובת: CE כותב אליה את הערך שוב ושוב, כמה פעמים בשנייה. המשחק מוריד את החיים, ו-CE מחזיר אותם מיד.

חשוב להבין מה זה **לא**: הקוד של המשחק עדיין רץ ועדיין מחסיר. אם מכה אחת מורידה יותר מכל החיים שלכם, תמותו בין כתיבה לכתיבה. הקפאה היא פתרון זריז ולא יציב. הפתרון האמיתי, שינוי הקוד שמחסיר, מגיע בשיעור 2.5.

## כשזה לא עובד

| מה קורה | סיבה סבירה | מה מנסים |
|---------|-------------|----------|
| אפס תוצאות כבר בסריקה הראשונה | הטיפוס שגוי | Float, אחר כך 2 Bytes, Byte, Double |
| התוצאות נעלמות אחרי סינון אחד | הערך שמוצג אינו הערך שנשמר | סריקת "ערך לא ידוע", בשיעור הבא |
| נשארות שתיים או שלוש כתובות | אחת אמיתית, והשאר עותקים לתצוגה | משנים כל אחת בנפרד ורואים מי משפיעה באמת |
| שיניתם את הערך והוא חוזר מיד לקדמותו | שיניתם עותק תצוגה | הכתובת האמיתית היא אחרת מהרשימה |
| הכתובת מפסיקה לעבוד אחרי הפעלה מחדש | הנתון דינמי | צריך pointer, בשיעור 2.3 |

השורה האחרונה היא הסיבה שהשיעור הזה הוא רק ההתחלה. כתובת שמצאתם תקפה עד שסוגרים את המשחק, בדיוק כמו שהסברנו בשיעור 1.3.

## מילון מונחים

| מונח | משמעות |
|------|--------|
| **Attach** | חיבור של CE לתהליך רץ |
| **First Scan** | סריקה חדשה של כל הזיכרון |
| **Next Scan** | סינון של התוצאות מהסריקה הקודמת |
| **Exact Value** | חיפוש של ערך מדויק |
| **Address list** | רשימת הכתובות ששמרתם, בתחתית החלון |
| **Freeze** | כתיבה חוזרת של ערך קבוע לכתובת |

## בדיקה עצמית

1. למה הסריקה הראשונה מחזירה אלפי תוצאות?
2. מה ההבדל בין First Scan ל-Next Scan?
3. הקפאתם את החיים על 100 ועדיין מתם ממכה אחת. למה?
4. חיפשתם 100 כ-4 Bytes וקיבלתם אפס תוצאות. מה הצעד הבא?
5. למה הכתובת שמצאתם לא תעבוד מחר?

תשובות: (1) כי הערך 100 מופיע במקרה במקומות רבים בזיכרון. (2) הראשונה סורקת הכול מחדש. השנייה מסננת את התוצאות הקיימות. (3) ההקפאה רק כותבת שוב ושוב. הקוד עדיין מחסיר, ומכה גדולה מספיק הורגת בין כתיבה לכתיבה. (4) לנסות Float, ואז טיפוסים אחרים. (5) הנתון מוקצה מחדש בכל הפעלה, בכתובת אחרת.
