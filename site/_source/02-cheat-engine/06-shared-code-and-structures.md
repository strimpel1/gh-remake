# שיעור 2.6 — Shared Code ומבני נתונים: מי נמצא ב-register

**מודול:** סריקת זיכרון עם Cheat Engine · **יחידות מקור:** Cheat Engine Shared OpCode (GH203), How to Use Cheat Engine's Struct Dissector, How To Find the EntityList

## הרעיון בקצרה

מפתחי משחקים לא כותבים פונקציה אחת לשחקן ועוד אחת לכל דמות אחרת. יש פונקציה אחת, והיא מקבלת pointer לדמות שעליה היא פועלת. לכן ההוראה שמעדכנת את החיים שלכם מעדכנת גם את החיים של כל השאר, וכל שינוי בה משפיע על כולם. לזה קוראים **shared code**. הפתרון: בתוך הקוד המוזרק בודקים **מי** נמצא ב-register לפני שמחליטים מה לעשות. כדי לבדוק, צריך למצוא במבנה שדה שמבדיל בין הדמות שלכם לאחרות, וזה מה שהשיעור הזה מלמד.

## לוודא שהקוד משותף

ב-Memory View, לחיצה ימנית על ההוראה, ואז **Find out what addresses this instruction accesses**. נפתח חלון שמתמלא בכתובות בכל פעם שההוראה רצה.

- הדמות שלכם נפגעת: מופיעה כתובת אחת.
- בוט נפגע: מופיעה כתובת נוספת.
- בוט אחר: עוד אחת.

כל כתובת כאן היא שדה החיים של דמות אחרת. אם מחסירים ממנה את ה-offset של החיים, מקבלים את בסיס המבנה של אותה דמות. עכשיו יש לנו כמה מבנים מאותו סוג, של דמויות שונות, וזה בדיוק מה שצריך כדי להשוות.

## Dissect data/structures: להשוות מבנים

1. ב-Memory View: **Tools** ואז **Dissect data/structures** (Ctrl+D).
2. בשורת הכתובת כותבים את בסיס המבנה של הדמות שלכם (הכתובת של החיים פחות ה-offset).
3. **Structures** ואז **Define new structure**. CE מנחש את טיפוסי השדות.
4. **File** ואז **Add extra address**, ומוסיפים את בסיסי המבנים של שתיים או שלוש דמויות אחרות. כל אחת מקבלת עמודה.

עכשיו כל שורה היא offset אחד, וכל עמודה היא דמות. CE צובע שורות שבהן הערכים שונים בין העמודות. אפשר לקבץ עמודות (הדמות שלכם בקבוצה אחת, הבוטים בשנייה) כדי שהצביעה תדגיש בדיוק את מה שמבדיל בין הקבוצות.

## מה מחפשים

שדה שערכו **זהה אצל כל הבוטים ושונה אצלכם**, ושלא משתנה במהלך המשחק:

| סוג שדה | איך הוא נראה | אמינות |
|---------|---------------|---------|
| מספר קבוצה (team) | 1 אצלכם, 2 אצל הבוטים | גבוהה |
| דגל "נשלט על ידי שחקן" | 1 מול 0, בדרך כלל Byte | גבוהה |
| pointer לבקר (controller, AI) | אצלכם pointer תקף, אצל הבוטים 0, או להפך | גבוהה |
| vtable, ארבעת הבתים הראשונים של המבנה | זהה לכל הבוטים ושונה אצלכם, אם אלה מחלקות שונות | גבוהה, אבל משתנה בעדכוני משחק |
| שם | מחרוזת או pointer למחרוזת | בינונית |
| מזהה ייחודי (ID) | שונה אצל כולם | לא שימושי להבחנה בין קבוצות |

שדות שנראים שונים אבל לא עוזרים: חיים, מיקום, זווית ותחמושת. הם שונים אצל כולם ומשתנים כל הזמן.

בדיקה שחוסכת טעויות: טוענים שלב אחר, או מפעילים את המשחק מחדש, ומוודאים שהשדה שבחרתם עדיין מבדיל באותו אופן.

## הסקריפט: בדיקה לפני פעולה

נניח שמצאנו שב-offset `0x224` יש 1 אצל הדמות שלכם ו-2 אצל הבוטים. הקוד המוזרק בודק קודם, ורק אז פועל:

```
newmem:
  cmp [ebx+00000224],1    // is this our own character?
  jne originalcode        // no: let the game do its normal thing
  mov eax,#100            // yes: write our own value

originalcode:
  mov [ebx+000000EC],eax

exit:
  jmp returnhere
```

זה כל הרעיון: השוואה, קפיצה מעל הקוד שלנו כשהתנאי לא מתקיים, ואז ההוראה המקורית. אותו שלד משמש לכל שינוי שאמור לחול רק על חלק מהדמויות.

זכרו את הכלל משיעור 2.5: `cmp` משנה את הדגלים. אם ההוראה שאחרי נקודת ההזרקה נשענת עליהם, עוטפים ב-`pushfd` ו-`popfd`.

## מהמבנה אל רשימת הישויות

חלון ה-Find out what addresses נתן לנו במקרה משהו חשוב: רשימה של כל הדמויות שהקוד נגע בהן. המשחק עצמו מחזיק רשימה כזו באופן מסודר, ה-**entity list**: מערך של pointers, אחד לכל דמות.

איך מוצאים אותה: לוקחים בסיס של מבנה של בוט ומחפשים אותו כערך (כמו בשיעור 2.3). אחת התוצאות תהיה בתוך רצף של pointers צמודים, 4 או 8 בתים זה מזה, שכל אחד מהם מצביע למבנה של דמות אחרת. זה המערך. ה-pointer אליו הוא נקודת הפתיחה למסלולים 7 ו-8, שבהם עוברים על כל הדמויות וקוראים את הנתונים של כל אחת.

## מילון מונחים

| מונח | משמעות |
|------|--------|
| **Shared code** | קוד אחד שמשרת כמה אובייקטים מאותו סוג |
| **Dissect data/structures** | הכלי של CE להצגה ולהשוואה של מבנים |
| **Entity** | אובייקט במשחק: דמות, ולפעמים גם פריט |
| **Entity list** | מערך ה-pointers לכל הישויות |
| **Team ID** | שדה שמציין לאיזו קבוצה שייכת דמות |
| **vtable** | pointer בתחילת אובייקט C++ לטבלת המתודות של המחלקה שלו |

## בדיקה עצמית

1. איך מוודאים שהוראה משרתת יותר מדמות אחת?
2. ברשימה של Find out what addresses מופיעה הכתובת `0B2004EC`, וה-offset של החיים הוא `0xEC`. מה בסיס המבנה?
3. למה שדה החיים אינו שדה טוב להבחנה בין דמויות?
4. מצאתם שדה ששווה 1 אצלכם ו-2 אצל הבוטים. מה הבדיקה שכדאי לעשות לפני שסומכים עליו?
5. איך נראית entity list בזיכרון?

תשובות: (1) Find out what addresses this instruction accesses, ואז גורמים להוראה לרוץ על דמויות אחרות ורואים אם מופיעות כתובות נוספות. (2) `0B200400`. (3) הוא שונה אצל כולם ומשתנה כל הזמן. (4) לטעון שלב אחר או להפעיל מחדש ולוודא שהוא עדיין מבדיל. (5) רצף של pointers צמודים, שכל אחד מצביע למבנה של ישות אחרת.
