# שיעור 2.7 — Floats, XMM ומכפילים

**מודול:** סריקת זיכרון עם Cheat Engine · **יחידות מקור:** Floating Point Values & XMM Registers (GH204), Floats - Defense & Damage Boost (GH207), Movement Speed Hack (GHS211)

## הרעיון בקצרה

לכתוב ערך קבוע זה שינוי גס. מעניין יותר לשנות **כמה**: פי שניים, חצי, פי אחד וחצי. בשביל זה צריך לעשות חשבון בתוך הקוד המוזרק, ורוב הערכים המעניינים במשחק הם floats. חשבון ב-float לא נעשה ב-registers הרגילים אלא ב-registers נפרדים, `xmm0` עד `xmm15`, עם סט הוראות משלהם. השיעור הזה מכסה את המעט שצריך כדי לכתוב סקריפט מכפיל.

## ההוראות של float

| הוראה | מה היא עושה | המקבילה למספרים שלמים |
|-------|-------------|--------------------------|
| `movss` | מעתיקה float אחד | `mov` |
| `addss` / `subss` | חיבור, חיסור | `add` / `sub` |
| `mulss` / `divss` | כפל, חילוק | `imul` / `idiv` |
| `comiss` / `ucomiss` | השוואה, מעדכנת דגלים | `cmp` |
| `cvtsi2ss` | ממירה מספר שלם ל-float | — |
| `cvttss2si` | ממירה float למספר שלם, בקיצוץ | — |
| `xorps xmm0,xmm0` | מאפסת register | `xor eax,eax` |

הסיומת `ss` פירושה scalar single: float אחד של 4 בתים. לגרסאות עם `sd` (למשל `movsd`, `mulsd`) אותה משמעות עבור double של 8 בתים.

קוד שמעדכן ערך שנשמר כ-float נראה למשל כך:

```
movss xmm0,[ebx+000000EC]   // xmm0 = the current value
subss xmm0,xmm1             // subtract the amount held in xmm1
movss [ebx+000000EC],xmm0   // store it back
```

המבנה זהה למה שקראנו בשיעור 1.5. רק השמות השתנו.

במשחקים ישנים של 32 ביט תפגשו גם את הדור הקודם, הוראות FPU: `fld` טוענת ערך, `fmul` מכפילה, `fstp` שומרת. ההיגיון דומה, אבל הן עובדות על מחסנית פנימית ולא על registers בעלי שם.

## קבועים בסקריפט

להוראות float אין צורה שמקבלת מספר ישירות. אי אפשר לכתוב `mulss xmm1,2.0`. המכפיל חייב לשבת בזיכרון, והסקריפט מגדיר לו מקום:

```
[ENABLE]
alloc(newmem,2048)
label(returnhere)
label(multiplier)

newmem:
  mulss xmm1,[multiplier]     // the amount, times our multiplier
  subss xmm0,xmm1             // the original instruction
  jmp returnhere

multiplier:
  dd (float)0.5

"game.exe"+2A1B0:
  jmp newmem
returnhere:

[DISABLE]
dealloc(newmem)
"game.exe"+2A1B0:
  subss xmm0,xmm1
```

`dd` כותב 4 בתים, ו-`(float)0.5` אומר ל-Auto Assembler לקודד את המספר כ-float. בלי זה, מספר שלם היה נכתב כמספר שלם, ואז נקרא כ-float זעיר וחסר משמעות.

שתי נקודות עדינות:

- **הקבוע יושב אחרי ה-`jmp`.** הוא נתון ולא קוד. אם המעבד יגיע אליו בריצה, הוא ינסה לבצע את הבתים שלו כהוראות.
- **ב-64 ביט** הפנייה ל-`[multiplier]` היא יחסית ל-`rip` ועובדת רק אם הקבוע קרוב לקוד. כשהוא באותו בלוק `alloc`, זה מובטח.

## מכפיל שאפשר לשנות מהטבלה

כדי לשנות את המכפיל בלי לערוך את הסקריפט, חושפים אותו כסמל:

```
label(multiplier)
registersymbol(multiplier)
```

ובחלק `[DISABLE]` מוסיפים `unregistersymbol(multiplier)`. עכשיו אפשר להוסיף לטבלה רשומה שהכתובת שלה היא המילה `multiplier`, מטיפוס Float, ולשנות את הערך בזמן שהמשחק רץ. אפשר גם לתת לה hotkeys של הגדלה והקטנה.

## כשהערך הוא מספר שלם

כשהערך הוא `int`, אפשר להכפיל ישירות:

```
newmem:
  imul edi,edi,2            // the amount, times 2
  sub [ebx+000000EC],edi    // the original instruction
```

`shl edi,1` עושה אותו דבר, כי הזזה בביט אחד היא כפל ב-2. למכפיל לא שלם, כמו 1.5, ממירים ל-float ובחזרה:

```
cvtsi2ss xmm0,edi           // int -> float
mulss xmm0,[multiplier]
cvttss2si edi,xmm0          // float -> int
```

אם `xmm0` בשימוש בקוד שמסביב, צריך לשמור ולשחזר אותו. אין `push` ל-registers של XMM, ולכן עושים את זה דרך ה-stack:

```
sub esp,10
movdqu [esp],xmm0
  ...
movdqu xmm0,[esp]
add esp,10
```

## דוגמה: מהירות תנועה

1. מוצאים את הקואורדינטות של הדמות (שיעור 2.4).
2. מפעילים עליהן **Find out what writes to this address** בזמן תנועה. ההוראה שמופיעה מוסיפה את המהירות למיקום.
3. מזהים את ה-register שמחזיק את המהירות, ומכפילים אותו בקוד מוזרק לפני ההוראה המקורית.
4. אם ההוראה משותפת לכל הדמויות, מוסיפים את הבדיקה משיעור 2.6.

כדאי להתחיל עם מכפיל קטן, 1.2 או 1.5. במכפילים גדולים הדמות עוברת דרך קירות או נופלת מהמפה, כי בדיקות ההתנגשות של המשחק נבנו למהירות הרגילה. זו דוגמה טובה לכלל רחב יותר: המשחק מניח הנחות על הערכים שלו, וערך שחורג מהן שובר דברים במקומות לא צפויים.

## מילון מונחים

| מונח | משמעות |
|------|--------|
| **XMM registers** | registers של 128 ביט שמשמשים לחשבון ב-float וב-double |
| **SSE** | סט ההוראות שעובד על XMM |
| **Scalar single (`ss`)** | float אחד של 4 בתים |
| **`dd`** | הנחיה שכותבת 4 בתים של נתונים לתוך הסקריפט |
| **`registersymbol`** | חשיפת label כשם שאפשר להשתמש בו בטבלה |
| **FPU** | יחידת הנקודה הצפה הישנה, עם הוראות כמו `fld` ו-`fstp` |

## בדיקה עצמית

1. למה אי אפשר לכתוב `mulss xmm1,2.0`?
2. מה היה קורה אילו כתבנו `dd 2` במקום `dd (float)2.0`?
3. למה הקבוע `multiplier` חייב להופיע אחרי ה-`jmp returnhere`?
4. ערך שמור ב-`edi` כמספר שלם ורוצים להכפיל אותו ב-1.5. מה שלושת הצעדים?
5. מהירות התנועה הוכפלה ב-5 והדמות נופלת דרך הרצפה. למה?

תשובות: (1) להוראות SSE אין צורה שמקבלת מספר ישירות. האופרנד חייב להיות register או זיכרון. (2) המספר השלם 2 היה נקרא כ-float זעיר מאוד, והתוצאה הייתה מתאפסת. (3) הוא נתון. אם המעבד יגיע אליו, הוא ינסה לבצע אותו כקוד. (4) המרה ל-float עם `cvtsi2ss`, כפל עם `mulss`, והמרה חזרה עם `cvttss2si`. (5) בדיקות ההתנגשות נבנו למהירות רגילה, וצעד גדול מדי מדלג מעליהן.
