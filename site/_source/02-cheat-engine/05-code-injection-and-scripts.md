# שיעור 2.5 — Code Injection וסקריפטים ב-Auto Assembler

**מודול:** סריקת זיכרון עם Cheat Engine · **יחידות מקור:** How to Make Cheat Engine Scripts (GH201), Cheat Engine Code Injection (GH202)

## הרעיון בקצרה

עד עכשיו שינינו **נתונים**: כתבנו ערך לכתובת, והמשחק דרס אותו שוב. הצעד הבא הוא לשנות את **הקוד** שכותב את הנתון. יש שתי רמות: להחליף הוראה ב-`nop`, שזה פשוט אבל גס, או **code injection**: להפנות את המשחק לקטע קוד קטן שכתבנו, שמחליט מה לעשות, ואז מחזיר אותו למקום. את שתיהן כותבים ב-**Auto Assembler**, שפת הסקריפטים של CE. כמו בכל המסלול, מתרגלים על התרגיל המובנה של CE ועל משחקי single-player.

## למצוא את ההוראה

1. מוצאים את הכתובת של הערך ומוסיפים לרשימה.
2. לחיצה ימנית, **Find out what writes to this address**, וגורמים לערך להשתנות במשחק.
3. בוחרים את ההוראה שהופיעה ולוחצים **Show disassembler**. נפתח Memory View כשההוראה מסומנת.

## רמה ראשונה: NOP

בחלון ה-debugger, לחיצה ימנית על ההוראה ואז **Replace with code that does nothing**. CE ממלא את הבתים שלה ב-`90`, והערך מפסיק להשתנות.

שני חסרונות, שכבר פגשנו בשיעור 1.5:

- אותה הוראה משרתת בדרך כלל את כל הדמויות במשחק, לא רק את שלכם.
- אין מקום להיגיון. `nop` רק מבטל. הוא לא יכול להכפיל, להשוות או לבחור.

## רמה שנייה: Code Injection

הרעיון בשלושה צעדים:

1. מקצים זיכרון חדש בתוך התהליך וכותבים בו את הקוד שלנו.
2. דורסים את ההוראה המקורית ב-`jmp` אל הזיכרון הזה.
3. בסוף הקוד שלנו קופצים חזרה, להוראה שאחרי המקורית.

```
game code                         our code (new memory)
...                               newmem:
jmp newmem      ------------->      (our logic)
nop                                 (the original instruction, if we still want it)
return:         <-------------      jmp return
...
```

פרט טכני אחד קובע הכול: `jmp` תופס **5 בתים**. אם ההוראה המקורית קצרה יותר, ה-`jmp` דורס גם את תחילת ההוראה הבאה, ולכן חייבים להעתיק לקוד שלנו את כל ההוראות שנפגעו. אם היא ארוכה יותר, ממלאים את השאר ב-`nop`. CE עושה את החשבון הזה בשבילכם.

## לתת ל-CE לכתוב את השלד

ב-Memory View, כשההוראה מסומנת: **Tools** ואז **Auto Assemble** (Ctrl+A). בחלון שנפתח: **Template** ואז **Cheat Table framework code**, ושוב **Template** ואז **Code injection**. מתקבל שלד כזה:

```
[ENABLE]
alloc(newmem,2048)
label(returnhere)
label(originalcode)
label(exit)

newmem:
  // your code goes here

originalcode:
  mov [ebx+000000EC],eax

exit:
  jmp returnhere

"game.exe"+2A1B0:
  jmp newmem
  nop
returnhere:

[DISABLE]
dealloc(newmem)
"game.exe"+2A1B0:
  mov [ebx+000000EC],eax
```

| חלק | מה הוא עושה |
|-----|-------------|
| `[ENABLE]` | רץ כשמסמנים את הסקריפט ברשימה |
| `alloc(newmem,2048)` | מקצה 2048 בתים של זיכרון חדש בתהליך |
| `label(...)` | מכריז על שם של מיקום בקוד |
| `newmem:` | כאן נכתב הקוד שלנו |
| `originalcode:` | ההוראה המקורית, שהועתקה כדי שלא תלך לאיבוד |
| `"game.exe"+2A1B0:` | המקום בקוד המשחק שנדרס ב-`jmp` |
| `[DISABLE]` | רץ כשמבטלים את הסימון: מחזיר את הבתים המקוריים ומשחרר את הזיכרון |

כדי להוסיף את הסקריפט לטבלה: **File** ואז **Assign to current cheat table**. הוא מופיע ברשימה כרשומה עם תיבת סימון, ואפשר לתת לו hotkey כמו לכל רשומה.

## סקריפט ראשון: ערך קבוע

במקום לתת למשחק לכתוב את הערך שחישב, כותבים ערך משלנו:

```
newmem:
  mov eax,#100

originalcode:
  mov [ebx+000000EC],eax
```

הסימן `#` אומר ל-Auto Assembler שהמספר עשרוני. בלי סימון, מספרים נקראים כ-hex, ו-`mov eax,100` היה כותב 256.

שימו לב שהשארנו את ההוראה המקורית: היא עדיין כותבת ל-`[ebx+EC]`, אבל עכשיו עם הערך שלנו ב-`eax`. זו גישה בטוחה יותר ממחיקה, כי כל מה שהמשחק מצפה שיקרה אחרי הכתיבה עדיין קורה.

## כללים לקוד מוזרק

- **שומרים על ה-registers.** אם הקוד שלכם צריך register לעבודה זמנית, דוחפים אותו ל-stack בהתחלה ושולפים בסוף (`push`, `pop`). זה הכלל משיעור 1.7: הקוד שמסביב סומך על הערכים שלו.
- **שומרים על ה-flags.** `cmp` משנה את הדגלים. אם ההוראה שאחרי נקודת ההזרקה היא קפיצה בתנאי שנשענת על השוואה מוקדמת, עוטפים את הקוד ב-`pushfd` ו-`popfd` (או `pushfq` ו-`popfq` ב-64 ביט).
- **לא מזריקים באמצע רצף רגיש.** אם בין הבתים שנדרסים יש יעד של קפיצה ממקום אחר בקוד, המשחק יקפוץ לאמצע ה-`jmp` שלכם ויקרוס. בוחרים נקודה אחרת, שורה או שתיים קודם.
- **ב-64 ביט המרחק משנה.** `jmp` של 5 בתים מגיע רק עד 2GB. הצורה `alloc(newmem,2048,"game.exe"+2A1B0)` מבקשת מ-CE להקצות קרוב לנקודת ההזרקה.

## מילון מונחים

| מונח | משמעות |
|------|--------|
| **Auto Assembler** | שפת הסקריפטים של CE: Assembly ועוד פקודות כמו `alloc` ו-`label` |
| **Code injection** | הפניית קוד המשחק לקטע קוד משלנו וחזרה |
| **Code cave** | אזור הזיכרון שבו יושב הקוד המוזרק |
| **`alloc` / `dealloc`** | הקצאה ושחרור של זיכרון בתהליך |
| **`[ENABLE]` / `[DISABLE]`** | מה רץ בהפעלת הסקריפט ובכיבויו |
| **Original code** | ההוראות שנדרסו על ידי ה-`jmp` והועתקו לקוד שלנו |

## בדיקה עצמית

1. למה `nop` על הוראה משפיע על יותר מדמות אחת?
2. ההוראה שרוצים להחליף תופסת 3 בתים. מה קורה להוראה שאחריה?
3. מה ההבדל בין `mov eax,100` ל-`mov eax,#100` ב-Auto Assembler?
4. מה חייב לקרות בחלק `[DISABLE]`?
5. הקוד המוזרק משתמש ב-`ecx` לחישוב זמני. מה צריך להוסיף?

תשובות: (1) אותה הוראה רצה לכל אובייקט מאותו סוג. (2) ה-`jmp` דורס גם את תחילתה, ולכן צריך להעתיק גם אותה לקוד המוזרק. (3) הראשון כותב 256, כי 100 נקרא כ-hex. השני כותב 100. (4) להחזיר את הבתים המקוריים ולשחרר את הזיכרון. (5) `push ecx` בהתחלה ו-`pop ecx` בסוף.
