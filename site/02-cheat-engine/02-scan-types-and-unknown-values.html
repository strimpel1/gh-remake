הרעיון בקצרה

סריקת ערך מדויק עובדת רק כשיודעים את המספר. אבל פס חיים בלי מספר, מד סיבולת, או ערך שהמשחק שומר בצורה שונה ממה שהוא מציג, לא נותנים לכם מה לכתוב בתיבת החיפוש. הפתרון: לא מחפשים ערך, מחפשים התנהגות. מתחילים מכל הזיכרון, ומסננים שוב ושוב לפי שאלה אחת: האם הערך עלה, ירד, השתנה או נשאר כמו שהיה.

ארבעת האחרונים זמינים רק ב-Next Scan, כי הם משווים לסריקה הקודמת.

סריקת ערך לא ידוע

המטרה: למצוא את פס החיים במשחק שמציג רק פס.

  1. Scan Type: Unknown initial value. Value Type: מתחילים ב-4 Bytes. לוחצים First Scan. CE שומר תמונה של כל הזיכרון, ומספר התוצאות יהיה מיליונים.
  2. חוטפים מכה. Scan Type: Decreased value, ואז Next Scan.
  3. לא עושים כלום כמה שניות. Scan Type: Unchanged value, ואז Next Scan. זה הצעד שרוב המתחילים מדלגים עליו, והוא החזק ביותר: הוא מעיף את כל הערכים שמשתנים מעצמם, כמו שעונים, מונים ואנימציות.
  4. מתרפאים. Increased value, ואז Next Scan.
  5. חוזרים על 2 עד 4, בסדר משתנה, עד שנשארות עשרות תוצאות ולא אלפים.
  6. מוסיפים את המועמדים לרשימה ובודקים אותם אחד אחד: משנים ורואים אם הפס זז.

שני כללים שמקצרים את התהליך:

  • Unchanged אחרי כל שינוי. אחרי כל צעד של "ירד" או "עלה", סיבוב אחד של Unchanged בלי לגעת בכלום.
  • לא מניחים כיוון. יש משחקים שסופרים נזק שנצבר במקום חיים שנותרו. חטפתם מכה, והערך עלה. אם Decreased מרוקן את הרשימה, מתחילים מחדש עם Changed value במקום.

Float: טווח ולא מספר

המסך מראה 87, ובזיכרון שמור 87.3406. חיפוש Exact Value של 87 כ-Float ייכשל. שתי דרכים:

  • Value between, עם 87 ו-88.
  • האפשרות Rounded (default) שמופיעה ליד תיבת הערך כשבוחרים Float. במצב הזה חיפוש של 87 מוצא גם 87.3. המצב Truncated מוצא כל ערך שמתחיל ב-87, והמצב Rounded (extreme) סלחני עוד יותר.

במקרה של הצפנה, הסריקה מביאה אתכם לכתובת אבל לא למספר שאפשר לכתוב. משם ממשיכים דרך הקוד שקורא את הערך, ב-debugger. זה הנושא של שיעור 2.3 ושל מסלול 3.

שתי הגדרות שכדאי להכיר

  • Fast Scan, מסומן כברירת מחדל עם הערך 4. CE בודק רק כתובות שמתחלקות ב-4, כי שם קומפיילרים מניחים משתנים. זה מהיר פי כמה, ורק לעיתים נדירות מפספס. אם אתם בטוחים בטיפוס ובערך ועדיין אין תוצאות, מבטלים את הסימון ומנסים שוב.
  • Writable. כברירת מחדל נסרק רק זיכרון שאפשר לכתוב אליו. ערכים של משחק נמצאים שם כמעט תמיד, ואין סיבה לשנות.

בדיקה עצמית

  1. למה Unchanged value הוא הסינון היעיל ביותר בסריקת ערך לא ידוע?
  2. חטפתם מכה, סיננתם Decreased, והרשימה התרוקנה. מה קרה כנראה?
  3. המסך מראה 50 חיים. חיפוש Exact Value של 50 כ-Float לא מוצא כלום. מה מנסים?
  4. מצאתם שהערך בזיכרון הוא 5000 כשהמסך מראה 50. מה כותבים כדי לקבל 999 חיים?
  5. מתי מבטלים את Fast Scan?

תשובות: (1) הוא מסיר את כל הערכים שמשתנים מעצמם, שהם רוב הרעש. (2) המשחק סופר נזק שנצבר, או שהטיפוס שגוי. מתחילים שוב עם Changed value. (3) Value between 50 ו-51, או מצב Rounded. (4) 99900, כי היחס הוא 100. (5) כשבטוחים בטיפוס ובערך ועדיין אין תוצאות.
