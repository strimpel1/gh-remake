למצוא Pointers: כתובת ששורדת הפעלה מחדש

מודול: סריקת זיכרון עם Cheat Engineיחידות מקור: Cheat Engine Pointer Scanning (GH105), Pointer Scan with Pointermaps, How To Hack Any Game - Pointers & EntityBase

הרעיון בקצרה

הכתובת שמצאתם בסריקה מתה כשסוגרים את המשחק. כדי להגיע לאותו נתון בכל הפעלה צריך pointer chain: כתובת סטטית ועוד רצף של offsets, בדיוק כמו בשיעור 1.4. ל-Cheat Engine יש שתי דרכים למצוא אותה. הדרך הידנית מלמדת אתכם איך המשחק בנוי. הדרך האוטומטית מהירה, אבל מחזירה אלפי תשובות שרובן שגויות. כדאי לדעת את שתיהן, ולהתחיל מהידנית.

הדרך הידנית: לעקוב אחרי הקוד

הרעיון: הקוד של המשחק יודע להגיע לנתון. אם נראה את ההוראה שנוגעת בו, נראה גם מאיפה היא לקחה את הכתובת.

  1. מוצאים את הכתובת של החיים בסריקה רגילה ומוסיפים אותה לרשימה.
  2. לחיצה ימנית על הכתובת, ובוחרים Find out what writes to this address (או F6). CE מצרף debugger לתהליך ופותח חלון ריק.
  3. חוטפים מכה במשחק. בחלון מופיעה הוראה, למשל:
mov [ebx+000000EC], eax
  1. לוחצים על ההוראה ואז על More information. בחלון שנפתח מופיעים ערכי ה-registers ברגע שההוראה רצה, למשל EBX=0A3F2000.

קראנו את השורה הזו כבר בשיעור 1.5: ebx הוא בסיס המבנה, ו-0xEC הוא ה-offset של החיים. עכשיו צריך לגלות מי מחזיק את 0A3F2000.

  1. סריקה חדשה: מסמנים את התיבה Hex, Value Type 4 Bytes (או 8 Bytes במשחק 64 ביט), ומחפשים את 0A3F2000. כל תוצאה היא מקום בזיכרון שמכיל את הכתובת הזו, כלומר pointer אל המבנה.
  2. מחפשים בתוצאות כתובת ירוקה. ב-CE ירוק פירושו כתובת סטטית, בתוך module. אם יש אחת, סיימתם: זו תחילת השרשרת.
  3. אין ירוקה? בוחרים אחת מהתוצאות וחוזרים לצעד 2 איתה, הפעם עם Find out what accesses this address (F5). כל סיבוב מוסיף רמה אחת לשרשרת.

להוסיף את ה-pointer לרשימה

  1. לוחצים Add Address Manually.
  2. מסמנים Pointer.
  3. בשדה התחתון כותבים את הכתובת הסטטית בצורה "game.exe"+18AC00.
  4. בשדה ה-offset שמעליו כותבים EC.
  5. לשרשרת ארוכה יותר לוחצים Add Offset. ה-offsets נכתבים מלמטה למעלה: הקרוב לבסיס למטה, האחרון למעלה.

CE מציג בזמן אמת לאן השרשרת מובילה, כך שרואים מיד אם היא מגיעה לערך הנכון. אחר כך סוגרים את המשחק, פותחים מחדש, ובודקים שהיא עדיין מראה את החיים.

הדרך האוטומטית: Pointer scan

כשהמעקב הידני מסתבך אחרי שלוש או ארבע רמות, נותנים ל-CE לחפש את כל המסלולים האפשריים.

  1. לחיצה ימנית על הכתובת, Pointer scan for this address.
  2. ההגדרות החשובות: Max level (כמה רמות, מתחילים ב-5) ו-Maximum offset value (המרחק המרבי בכל רמה, ברירת המחדל 2047 בדרך כלל מספיקה).
  3. שומרים את קובץ התוצאות. יתקבלו מאות אלפי מסלולים, ורובם יעבדו רק עכשיו ובמקרה.
  4. סוגרים את המשחק, פותחים מחדש, ומוצאים שוב את הכתובת של החיים בסריקה רגילה.
  5. בחלון ה-Pointer scan בוחרים Pointer scanner ואז Rescan memory, ומזינים את הכתובת החדשה. נשארים רק מסלולים שמובילים אליה גם עכשיו.
  6. חוזרים על 4 ו-5 כמה פעמים, רצוי גם אחרי החלפת שלב ואחרי מוות של הדמות.

כשנשארים כמה עשרות מסלולים, בוחרים לפי שלושת הסימנים משיעור 1.4: קצר, מתחיל ב-module של המשחק עצמו, ועם offsets קטנים והגיוניים.

Pointermaps: אותו דבר, מדויק יותר

במקום לסנן אחרי הסריקה, אפשר לתת ל-CE שתי תמונות מצב מראש:

  1. מוצאים את הכתובת, לחיצה ימנית, Generate pointermap, ושומרים קובץ.
  2. מפעילים את המשחק מחדש, מוצאים שוב את הכתובת, ויוצרים pointermap שני.
  3. מפעילים Pointer scan, מסמנים Use saved pointermap ו-Compare results with other saved pointermap(s), ומזינים לכל קובץ את הכתובת שהייתה נכונה באותה ריצה.

התוצאה היא רשימה קצרה בהרבה כבר מההתחלה, כי כל מסלול חייב להיות תקף בשתי הריצות.

בדיקה עצמית

  1. ראיתם mov [esi+14], ecx וב-More information כתוב ESI=0B200400. מה ה-offset, ומה מחפשים עכשיו?
  2. מה המשמעות של כתובת ירוקה ב-CE?
  3. למה חייבים להפעיל את המשחק מחדש באמצע pointer scan?
  4. נשארו לכם 40 מסלולים. לפי מה בוחרים?
  5. למה כדאי להתחיל בדרך הידנית גם כשהאוטומטית מהירה יותר?

תשובות: (1) ה-offset הוא 0x14. מחפשים את הערך 0B200400 ב-hex כדי למצוא מי מצביע על המבנה. (2) כתובת סטטית בתוך module, שנשארת במקומה ביחס ל-base. (3) כדי לסנן מסלולים שתקפים רק בריצה הנוכחית. (4) קצר, מתחיל ב-module של המשחק, offsets קטנים. (5) היא מלמדת את מבנה המשחק, והמסלול שמתקבל הוא זה שהמשחק עצמו משתמש בו.
