טיפוסי נתונים: איך ערכים נראים בזיכרון

מודול: יסודותיחידות מקור: CS420 5 - Memory Editing & Data Types, Low Level C Data Types

סרטון השיעור (באנגלית)

הרעיון בקצרה

בזיכרון אין "מספרים" ואין "טקסט". יש רק בתים. טיפוס הנתונים (data type) הוא ההחלטה איך לפרש אותם: כמה בתים לקרוא, והאם הם מספר שלם, מספר עם נקודה או תו. אותם ארבעה בתים יכולים להיות 1,120,403,456 או 100.0, תלוי רק בשאלה איך קוראים אותם. כשמחפשים ערך במשחק ולא מוצאים, ברוב המקרים הסיבה היא שחיפשנו בטיפוס הלא נכון.

הטווחים בטבלה הם לקריאה בלי סימן. גודל ה-pointer נקבע לפי התהליך: 4 בתים בתהליך של 32 ביט, 8 בתים בתהליך של 64 ביט.

כלל אצבע: מה שנספר ביחידות שלמות הוא בדרך כלל int. מה שזז ברצף (מיקום, זווית, מהירות) הוא כמעט תמיד float.

Little-endian: הבתים הפוכים

מעבדי x86 ו-x64 שומרים מספר בן כמה בתים כשהבית הפחות משמעותי ראשון. הסדר הזה נקרא little-endian. המספר 1000 הוא 0x000003E8, ובזיכרון הוא נראה כך:

value:      0x000003E8   (1000)
in memory:  E8 03 00 00

כלים כמו Cheat Engine הופכים את הסדר בשבילכם כשהם מציגים ערך. אבל בתצוגת בתים גולמית (hex view) רואים את הסדר האמיתי. מי שמחפש את רצף הבתים 00 00 03 E8 לא ימצא כלום.

מספרים שלמים עם סימן

int יכול להיות unsigned (בלי סימן, רק אי-שליליים) או signed (עם סימן). ההבדל הוא רק בפירוש. מספרים שליליים נשמרים בשיטת two's complement, שבה הביט העליון מסמן שלילי:

מכאן נובעת תופעה מוכרת: מוסיפים 1 לערך המרבי, והוא "מתגלגל" לערך השלילי ביותר. זה נקרא integer overflow, והוא ההסבר לבאגים שבהם כסף במשחק הופך פתאום למינוס שני מיליארד.

Float: מספרים עם נקודה

float נשמר לפי תקן IEEE 754: ביט אחד לסימן, 8 ביטים למעריך (exponent) ו-23 ביטים לשבר. לא צריך לחשב את זה ביד, אבל צריך לדעת איך זה נראה:

100.0 as float:  0x42C80000   in memory: 00 00 C8 42
100   as int:    0x00000064   in memory: 64 00 00 00

שלוש מסקנות מעשיות:

  • אותו ערך על המסך, בתים שונים לגמרי. אם המשחק שומר חיים כ-float, חיפוש של 100 כ-4 Bytes לא ימצא אותם.
  • מה שמוצג אינו בהכרח מה שנשמר. המסך מראה 87, ובזיכרון יש 87.3406. לכן ב-float מחפשים טווח ("בין 87 ל-88") ולא ערך מדויק.
  • float שנקרא בטעות כ-int נראה כמו מספר ענק סביב מיליארד. כשרואים ערכים כמו 1,120,403,456 ליד נתוני שחקן, כדאי לנסות להציג אותם כ-float.

טקסט

מחרוזת (string) היא רצף של תווים שמסתיים בבית אפס (null terminator). יש שני קידודים נפוצים ב-Windows:

"Bob" as ASCII:   42 6F 62 00
"Bob" as UTF-16:  42 00 6F 00 62 00 00 00

ב-UTF-16 כל תו תופס שני בתים, ולכן בין האותיות האנגליות מופיעים אפסים. ב-Cheat Engine זו האפשרות Unicode בחיפוש מחרוזות. אם חיפוש שם שחקן נכשל, מנסים את הקידוד השני.

Struct: כמה ערכים ברצף

משחק לא שומר את החיים של השחקן לבד. הוא שומר מבנה (struct) שמרכז את כל נתוני השחקן, שדה אחרי שדה:

struct Player {
    int   health;    // offset 0x00
    int   armor;     // offset 0x04
    float x;         // offset 0x08
    float y;         // offset 0x0C
    float z;         // offset 0x10
    char  name[16];  // offset 0x14
};

ה-offset של כל שדה הוא סכום הגדלים של השדות שלפניו. אם המבנה מתחיל ב-0x00F8A3C0, אז armor נמצא ב-0x00F8A3C4 ו-z ב-0x00F8A3D0.

שני דברים נובעים מזה:

  • מצאתם שדה אחד, מצאתם את השכנים. שלושה floats צמודים שמשתנים כשזזים הם כמעט בוודאות קואורדינטות X, Y, Z. זה הבסיס לכל מיפוי מבנים בהמשך הקורס.
  • Padding. הקומפיילר מיישר שדות לכתובות נוחות למעבד. char שאחריו int יתפוס בפועל ארבעה בתים, שלושה מהם ריקים. לכן offsets במבנה אמיתי לא תמיד תואמים חישוב נאיבי, וחורים של כמה בתים בין שדות הם דבר רגיל.

איך מנחשים טיפוס של ערך לא מוכר

  1. נספר ביחידות שלמות? מתחילים ב-4 Bytes.
  2. לא נמצא? מנסים Float, ואחריו 2 Bytes, Byte ו-Double.
  3. מוצג כפס או באחוזים בלי מספר? כנראה float בין 0 ל-1, או בין 0 ל-100. מחפשים "ערך לא ידוע" ומסננים לפי עלה או ירד. זו הטכניקה המרכזית של מסלול 2.
  4. הערך בזיכרון שונה מהמסך? יש משחקים שמכפילים (87 נשמר כ-870) או מצפינים ערכים. חוזרים לחיפוש לפי שינוי.

בדיקה עצמית

  1. איך נראה המספר 258 כ-int בזיכרון, בית אחרי בית?
  2. חיפשתם חיים בערך 100 כ-4 Bytes ולא נמצא דבר. מה שני הדברים הראשונים שתנסו?
  3. מה הערך של FF FF FF FF כ-signed int? ומה כ-unsigned?
  4. במבנה Player שלמעלה, מה ה-offset של name? למה?
  5. ראיתם בזיכרון 41 00 6C 00 69 00 00 00. מה זה כנראה?

תשובות: (1) 02 01 00 00, כי 258 הוא 0x0102 והסדר הפוך. (2) חיפוש כ-Float, ואז חיפוש "ערך לא ידוע" עם סינון לפי שינוי. (3) 1-, ו-4,294,967,295. (4) 0x14, כי לפניו חמישה שדות של 4 בתים. (5) המחרוזת "Ali" בקידוד UTF-16.
