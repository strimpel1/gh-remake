מודול: יסודותיחידות מקור: Learn Assembly for Game Hacking, CS420 8 - How to Edit Assembly, Stack Pointers Explained

סרטון השיעור (באנגלית)

הרעיון בקצרה

Assembly היא הצורה הקריאה של קוד מכונה: כל שורה היא הוראה אחת למעבד. לא צריך לדעת לכתוב תוכנות ב-Assembly. צריך לדעת לקרוא עשר שורות ולהבין מה הן עושות לנתון שמעניין אותנו. כמעט כל מה שרואים בפועל מורכב מקומץ הוראות: העתקה, חשבון, השוואה וקפיצה. השיעור משתמש בתחביר Intel, שהוא ברירת המחדל ב-Cheat Engine, ב-x64dbg וב-IDA.

Registers: המשתנים של המעבד

Register הוא תא אחסון קטן ומהיר בתוך המעבד. ב-x64 כל register הוא 64 ביט, ואפשר לפנות גם לחלקים שלו:

בתהליך של 32 ביט קיימים רק השמות שמתחילים ב-e. מספרים עם נקודה חיים ב-registers נפרדים, xmm0 עד xmm15.

הוראה, יעד, מקור

המבנה הוא תמיד instruction destination, source. היעד בא ראשון:

mov eax, 5        ; eax = 5
mov eax, ebx      ; eax = ebx
add eax, 2        ; eax = eax + 2

סוגריים מרובעים פירושם זיכרון. זה אותו dereference מהשיעור הקודם:

mov eax, ebx          ; copy the value of ebx into eax
mov eax, [ebx]        ; read 4 bytes from the address stored in ebx
mov eax, [ebx+0xEC]   ; read from address ebx + 0xEC
mov [ebx+0xEC], eax   ; WRITE eax to address ebx + 0xEC

השורה האחרונה היא הדפוס החשוב ביותר בקורס: ebx מחזיק את כתובת מבנה השחקן, 0xEC הוא ה-offset של השדה, וההוראה כותבת לשדה ערך חדש. כשמוצאים שורה כזו למדנו שני דברים בבת אחת: מה ה-offset של השדה, ואיזה register מחזיק את בסיס המבנה.

תנאים: cmp ואז קפיצה

if ב-C הופך לשתי הוראות. cmp משווה ומעדכן את ה-flags, והוראת הקפיצה שאחריה מחליטה לפיהם:

cmp dword ptr [ebx+0xEC], 0   ; compare health with 0
jg  still_alive               ; jump if greater (health > 0)
call player_died              ; reached only when health <= 0
still_alive:

שימו לב שהקפיצה הרבה פעמים הפוכה מהתנאי בקוד המקור: הקומפיילר קופץ מעל הבלוק כשהתנאי לא מתקיים.

ה-Stack ופונקציות

ה-stack הוא אזור זיכרון שגדל כלפי כתובות נמוכות. rsp מצביע תמיד על הראש שלו. push מקטין את rsp וכותב, pop קורא ומגדיל.

call דוחפת ל-stack את הכתובת של ההוראה שאחריה (כתובת החזרה) וקופצת לפונקציה. ret שולפת את הכתובת הזו וקופצת אליה חזרה. פונקציה אופיינית ב-32 ביט נפתחת ונסגרת כך:

push ebp            ; save the caller's frame base
mov  ebp, esp       ; start our own frame
sub  esp, 0x10      ; reserve 16 bytes for local variables
...
mov  esp, ebp       ; release the locals
pop  ebp            ; restore the caller's frame base
ret

בתוך פונקציה כזו, [ebp+8] הוא הפרמטר הראשון ו-[ebp-4] הוא משתנה מקומי. איך בדיוק פרמטרים עוברים בין פונקציות (calling conventions) זה נושא לשיעור נפרד.

דוגמה מלאה: קוד שמוריד חיים

נניח שעצרנו על ההוראה שכותבת לשדה החיים, ואלה השורות שסביבה:

mov  eax, [ebx+0xEC]     ; 1. eax = current health
sub  eax, edi            ; 2. eax = health - damage
mov  [ebx+0xEC], eax     ; 3. store the new health
test eax, eax            ; 4. is it zero or below?
jg   0x0042A1C0          ; 5. still alive -> skip ahead
call 0x0042B300          ; 6. otherwise handle death

מה למדנו מקריאה בלבד:

  • ebx מחזיק את בסיס מבנה הדמות, והחיים נמצאים ב-offset 0xEC.
  • edi מחזיק את כמות הנזק.
  • שורה 3 היא הכתיבה היחידה לשדה. אם מחליפים אותה ב-nop, החיים לא יורדים.

הניסוי האחרון הוא התרגיל הקלאסי של התחום, והוא מלמד גם את המלכודת הקלאסית: אותו קוד משרת בדרך כלל גם את האויבים. ebx מצביע על מי שנפגע עכשיו, לא דווקא על השחקן, ולכן אחרי ה-nop גם האויבים מפסיקים לאבד חיים. הפתרון, בדיקה של מי נמצא ב-ebx לפני שמחליטים, הוא נושא במסלול 2.

עוד פרט טכני: כשמחליפים הוראה, חייבים למלא בדיוק את אותו מספר בתים. שורה 3 תופסת 6 בתים, ולכן מחליפים אותה בשישה nop. אחרת כל ההוראות שאחריה יפוענחו לא נכון והמשחק יקרוס.

בדיקה עצמית

  1. מה ההבדל בין mov eax, ebx לבין mov eax, [ebx]?
  2. מה ההבדל בין mov eax, [ebx+8] לבין lea eax, [ebx+8]?
  3. ראיתם sub [esi+0x150], eax בקוד שרץ בכל ירייה. מה אפשר להסיק?
  4. למה xor eax, eax נפוץ יותר מ-mov eax, 0?
  5. החלפתם הוראה של 6 בתים ב-nop אחד והמשחק קרס. למה?

תשובות: (1) הראשון מעתיק את הערך של ebx. השני קורא מהזיכרון בכתובת ש-ebx מחזיק. (2) mov קורא את מה ששמור בכתובת. lea שם ב-eax את הכתובת עצמה. (3) esi מחזיק בסיס של מבנה, כנראה נשק. ב-offset 0x150 יש את התחמושת, ו-eax הוא מספר הכדורים שיורדים. (4) הוא מקודד בפחות בתים והתוצאה זהה. (5) חמשת הבתים שנשארו פוענחו כהוראות חדשות וחסרות משמעות.
